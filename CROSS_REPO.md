# Cross-repository inbox

Obligations and corrections that cross a repository boundary, as typed rows so a
test can check them. `PLAN.md`'s *Notes outbound* section was the right idea with
no mechanism: two of its entries were applied elsewhere and nothing here knew, and
four more obligations accumulated in three other documents.

**The rule this file exists for.** A note that names a symbol is a claim about
whichever repository owns it, and a claim nobody checks rots exactly as fast as a
status word does — which `test_plan_is_true.py` learned the hard way.
`tests/test_cross_repo.py` resolves every `symbol` by `ast`, importing nothing,
and skips by name when the owning repository is not on disk. That is what
`ELSEWHERE` already does for paths, generalised one step.

**The symbol is qualified by its owner, `repo:path::Name`, and not by the
`to` column.** The first version of this file assumed the symbol lived in the
target, which is wrong half the time: a correction *sent* to the benchmark is
usually about a symbol here. Five of the eight seed rows failed on that, and one
failed for the better reason — it named `png_bias`, which has never existed; the
function is `png_bias_shift`. A wrong symbol in a cross-repo note is precisely
what this file is for, and it found one before the file was finished.

## Status vocabulary

| status | means |
|---|---|
| `open` | stated, not yet acted on by the target |
| `applied` | the target changed in response |
| `settled` | the disagreement was resolved by agreement or measurement, with no code change owed |
| `refused` | the target measured it and declined, with the number recorded |
